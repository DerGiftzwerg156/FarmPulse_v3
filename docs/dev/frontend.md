# Frontend (Angular) – decisions

| Topic | Decision | Reason |
| --- | --- | --- |
| Framework | Angular 22, standalone components, strict TypeScript, Angular Router | Current stable at implementation time (checked 2026-09-25). |
| Node | Angular CLI 22 requires Node ≥ 22.22.3 / 24.15; the project uses Node 24 LTS. | CLI hard requirement. |
| Styling | Tailwind CSS 4 with the binding `tailwind.config.js` (tokens extracted from `docs/design-reference/Dashboard.html`), loaded through `@config` in `src/styles.css`; custom `fp-*` utilities copied 1:1 from the reference. | Keeps the concept's config file while using the current Tailwind major. |
| Fonts | Google Fonts `Chakra Petch` (500/600/700, display) and `Barlow` (400/500/600, body). | Same source as the design reference. |
| i18n | Own `TranslationService` + `t` pipe with `src/app/core/i18n/de.json`; no hard-coded German strings in templates. | `@angular/localize` needs one build per locale and extraction tooling; V1 is German-only but must stay extensible – a JSON dictionary per locale is enough and switchable at runtime. |
| Visual acceptance | Internal route `/dev/style-guide` (only in the development build via `environment.styleGuide`) instead of Storybook. | No extra toolchain; the page renders every shared component with sample data and is also used by the screenshot generator. |
| Unit tests | Vitest via `@angular/build:unit-test` (Angular 22 default, jsdom), coverage via `@vitest/coverage-v8`. `npm test -- --watch=false [--coverage]`. | The work plan offers Jest or Karma/Jasmine: Karma is deprecated by Angular, Jest needs a separate builder/preset that lags behind Angular majors. Vitest is Angular's own default runner since v21, shares Jest's API (`describe/it/expect/vi`), runs headless in jsdom (no browser in CI) and needs no extra configuration. |
| E2E tests | Playwright (`npm run e2e`), starts bridge simulator + backend (profile `e2e`) + dev server itself. | Tests real flows through the file bridge; see `docs/dev/testing.md`. |
| Lint | angular-eslint (`npm run lint`). | Standard Angular lint setup. |
| Dev proxy | `proxy.conf.json` forwards `/api` to `http://localhost:8080`. | Frontend uses relative `/api` URLs in every environment. |
| Global state | Angular Signals (`GameStateStore`) instead of an RxJS store/NgRx. Live events bump `mailVersion`/`callVersion`/`diaryVersion`/`stateVersion`; feature pages react through `effect()`/`computed()` and reload via REST. | State is tiny (header context + counters); Signals are Angular's native reactivity, need no extra library and work zoneless. Events only carry ids, the REST API stays the single source of truth. |
| Live updates | `LiveEventsService` consumes `GET /api/events/stream` with `EventSource`; on `hello` it marks the store as connected and refreshes, on `mail`/`call`/`state` it refreshes the header counters. On error it closes the source and reconnects itself with a stepped backoff (1 s, 2 s, 5 s, 10 s, 30 s …). The `EventSource` is created through the `EVENT_SOURCE_FACTORY` token so tests use `src/testing/fake-event-source.ts`. | Own reconnect gives deterministic behaviour (the browser's built-in retry stops on some HTTP errors) and is testable with fake timers. |
| Shared UI (AP-7.3) | `shared/ui`: card, stat, badge, button, modal, toasts, list item, icon (inline Lucide paths), page error, chart wrapper. Visual acceptance on `/dev/style-guide` and in `docs/screenshots`. | Small, dependency-free set matching the design reference 1:1. |
| Charts | Own SVG line chart (`ChartWrapper`) instead of a chart library: one y-axis, 2 px lines, legend for ≥ 2 series, direct end labels for ≤ 4 series (hidden below 480 px), crosshair tooltip, table view. Width measured with a `ResizeObserver` so text keeps its real size. Categorical palette validated for the dark surface (`SERIES_COLORS`); color follows the sell point, never the rank. | One chart type needed; a library would add ~100 kB and fight the design tokens. |
| Feature pages (Phase 8) | One lazily loaded standalone component per area under `features/<area>`; routes in `app.routes.ts`, titles are i18n keys (`I18nTitleStrategy`). Pages reload via `effect()` on the store's version signals. | Small initial bundle; live updates without polling. |
| Forms vs. free text | Every value that moves money is a typed form field (`type="number"`, `step="any"`); free text only for mails, calls, interview questions, notes and the backstory. Mails that require a form carry `formLink` (e.g. `/bank?application=5`), the mailbox shows *Zum Formular* instead of a reply box; pages read the query parameter via router input binding. | Two-tier principle: the backend never extracts numbers from text. |
| No formula disclosure | Trust = 5-segment meter + word (`TrustMeter`), village reputation = tier, credit rejection = reason category; scores never reach the browser (the API does not send them). | Functional concept: role play instead of numbers. |
| Errors | `apiErrorMessage`/`toPageError` show the backend's German `ApiError.message`; `NO_ACTIVE_SAVEGAME` turns into an onboarding hint (`PageErrorView`). | Consistent, translated messages from one source. |
| Calls | Global `CallOverlay` in the shell (SSE-triggered) for RINGING calls; the "soft time window" after accepting is a purely cosmetic 90 s countdown (`SOFT_WINDOW_SECONDS`) without any effect. | Technical concept "Anruf-Zustandsautomat": no backend timeout after ACCEPTED. |
| Secrets | The API key exists only in the settings form until it is PUT to the backend; it is never read back or stored in browser storage (tested). | AP-8.11. |
| Release | The backend serves `dist/frontend/browser` when `rpsim.web.static-dir` is set (SPA fallback), so players start one process. | See `configuration-reference.md`. |
